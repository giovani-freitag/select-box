# 11. Render every docs demo as a real island, on one page

- Status: accepted
- Date: 2026-08-26

## Context

A multi-framework library's docs have to show the same component in five
frameworks. The common answer is an iframe per demo — a sandbox boundary that
hides the thing the docs are trying to prove, costs a page load each, and styles
nothing like the surrounding page.

## Decision

The site is Astro + Starlight, and each framework demo is an Astro Island on the
same page: `client:only="react"` and `client:only="vue"` for the two component
frameworks, a plain `<script>` for Lit, the web component and jQuery. A framework
switcher tabs between them. No iframe, no sandbox boundary — five real wrappers
running in one document, which is itself the claim the library makes.

Each demo folder is self-contained: the data is inlined per framework, and the
snippet shown beside the demo is extracted from that same source file through
`// #region snippet` markers. Displayed code and running code cannot diverge.

API reference is generated by TypeDoc into Markdown, and a small script prepends
Starlight frontmatter before Astro picks it up.

## Consequences

- The demos are styled by the shipped stylesheet plus a token-mapping theme
  file, so the docs are the real stylesheet re-themed rather than a parallel
  implementation of it (see [ADR 12](0012-ship-one-stylesheet-driven-by-tokens.md)).
- The site pulls React, Vue, Lit and jQuery into one build, which makes it the
  heaviest package in the workspace.
- The site's `<script>` blocks were the one place no checker reached, and it cost
  three live demos that kept building green while dying at load. Two layers close
  it: `astro check` is now the docs package's `typecheck`, and a Playwright guard
  drives every demo on the built site and fails on any console error.
- Publishing goes to GitHub Pages under a repository sub-path, so internal links
  in content are relative and components resolve theirs through `BASE_URL`.
