## How it stays fast

- **Only visible rows are in the DOM.** The default 240 px popover with 28 px
  rows keeps about a dozen nodes live at any moment — the window plus a small
  overscan — regardless of the source array's size.
- **Each label is normalised once, not once per keystroke.** Lower-casing and
  stripping diacritics is the expensive half of a substring match, so the result
  is cached per option, and the cache is filled ahead of time in the browser's
  idle slices. At 100 000 options a keystroke costs around 10–20 ms, with no
  throttling in the way.
- **Keyboard nav scrolls into view in O(1).** Moving past the visible window
  jumps directly to the target offset, no DOM diffing.
