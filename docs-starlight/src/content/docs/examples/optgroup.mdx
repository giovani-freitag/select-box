Two ways to group: a `group?: string` key on each flat option (cheaper, no
metadata), or a pre-built `groups: SelectGroup[]` array (when you need group
labels, disabled flags, or explicit ordering).

## When to use `groups` instead

The flat shape is cheapest — the controller normalizes it into ordered groups
under the hood. Reach for `groups: SelectGroup[]` when:

- The **order of headers must be explicit** (flat-with-key honors first-seen order, which depends on the array).
- A whole **group should be disabled** (`disabled: true` on the group skips keyboard nav for every option inside).
- The group needs **a different display label** than its key.

```ts
import type { SelectGroup } from "@select-box/core";

const fruits: SelectGroup[] = [
    {
        key: "pomes",
        label: "Pomes",
        options: [
            { value: "apple", label: "Apple" },
            { value: "pear", label: "Pear" },
        ],
    },
    {
        key: "stone",
        label: "Stone fruits",
        disabled: true,            // whole group skipped by keyboard nav, dimmed in the list
        options: [
            { value: "peach", label: "Peach" },
            { value: "plum", label: "Plum" },
        ],
    },
];

<SelectBox groups={fruits} placeholder="Pick a fruit" />;
```

You can also **combine** the two — pass `groups` for the metadata-rich ones plus
`options` for the rest. The controller merges them in declaration order.

## How filtering interacts with groups

When the user types, every group's options are filtered independently. Groups
that end up empty are dropped from `snapshot.filteredGroups` — the user only
sees headers that still have at least one match. Keyboard navigation skips
empty groups and disabled options automatically.
