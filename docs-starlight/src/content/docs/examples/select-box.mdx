## Option shape

`options` is a flat array. Items that share a `group` key render under one
heading; items without a `group` fall under whatever `ungroupedLabel` you
pass (or stay un-headed when omitted).

```ts
interface SelectOption<TExtra extends object = object> {
    value: string;          // unique identifier — coerced to string on input
    label: string;          // shown in the trigger and the list
    disabled?: boolean;
    group?: string;
    // + everything from TExtra rides on the same object
}
```

`TExtra` is the optional payload generic — pass it when you want to carry
extra domain fields (`id`, `slug`, icons, etc.) typed all the way through
to `onChange` / `selectedOption`.

## Props / Attributes

| Field | React prop | Custom-element |
|---|---|---|
| Options | `options` | `.options` (property) |
| Grouping | a `group` key on each option | same, on `.options` |
| Ungrouped heading | `ungroupedLabel` | `ungrouped-label` attribute |
| Selection you own | `value` | `.value` (property) |
| Selection it owns | `defaultValue` | `value` attribute (the seed; the property is the live one, as with `<input>`) |
| Change callback | `onChange(value, option)` | `change` event (read `event.target.value` / `event.target.selectedOption`) |
| Vue two-way binding | — | `v-model`, or `:value` with `@change` |
| Popover opened / closed | `onOpen` / `onClose` | `open` / `close` events |
| Popover side | measured, not configured — see below | same |
| Multi-select | `multiple` | `multiple` attribute |
| Surface | `surface` (`"popover"` \| `"inline"`) | `surface` attribute |
| Placeholder | `placeholder` | `placeholder` attribute |
| Empty-state text | `emptyMessage` | `empty-message` attribute |
| Submitted under | `name` | `name` attribute |
| Required | `required` | `required` attribute |
| Refuses everything | `disabled` | `disabled` attribute |
| Refuses edits, still submits | `readOnly` | `readonly` attribute |
| Accessible name | `aria-label` / `aria-labelledby` | same attributes |
| Identifies the component | `id` (lands on the root) | `id` attribute |
| What `<label for>` targets | `inputId` (lands on the trigger input) | — |
| Touched / focus | `onBlur` / `onFocus` | native `blur` / `focus` |
| Inline styles | `style` (lands on the root) | `style` attribute |
| Addons | `addons` | `.addons` (property) |
| Custom filter | `filter` | `.filter` (property) |
| Root and controller | `ref` yields `{ root, controller }` | `.root` / `.controller` (getters) |

### Which side the popover opens on

The list opens downward, and flips upward when it would not fit below and there
is more room above — the same call a native `<select>` makes. The core measures
and publishes the answer on the popover as `data-select-placement="below"` or
`"above"`; the stylesheet positions each side. It re-measures while the popover
is open, so scrolling the page moves the list to whichever side still fits.

One thing to know if you wrap the box: an ancestor with `overflow: hidden` clips
a popover that opens upward.

### Why `open` and `close` are props in React

Every wrapper dispatches `open` and `close` as real DOM events, which bubble
like any other. React's synthetic event system routes a fixed list of event
names, so a custom one on a component has no listener syntax — a `ref` and a
manual `addEventListener` would be the only way. The props are React's door to
the same two moments, with the same names.

## Keyboard

| Key | Action |
|---|---|
| `↓` / `↑` | Move active option (skips disabled). When closed, `↓` also opens the popover. |
| `Enter` | Commit the active option. |
| `Escape` | Close the popover. |
| Click outside | Close the popover. |
