Two layers per wrapper, driving the same controller. Start at the top and drop
down only when you hit something props cannot say.

## Ready-to-use component

A drop-in component. Trigger, popover, search, list, keyboard navigation,
ARIA and addon-driven controls are already wired — you write no select-box
markup at all.

<Tabs>
  <TabItem label="React">

```tsx
import { SelectBox } from "@select-box/react";

<SelectBox
    options={fruits}
    placeholder="Pick a fruit"
    onChange={(value) => console.log(value)}
/>;
```

  </TabItem>
  <TabItem label="Web Components">

```html
<select-box id="fruit" placeholder="Pick a fruit"></select-box>

<script type="module">
    import "@select-box/webcomponents";
    const element = document.getElementById("fruit");
    element.options = fruits;
    element.addEventListener("change", (event) => {
        console.log(event.target.value);
    });
</script>
```

  </TabItem>
</Tabs>

## Headless

When the default markup does not fit, take the snapshot and the controller and
render your own. Behaviour, keyboard navigation and ARIA stay where they were —
in the core.

<Tabs>
  <TabItem label="React">

```tsx
import { useSelectBox } from "@select-box/react";

function MySelectBox() {
    const { state, controller } = useSelectBox({ options: fruits });
    return (
        <div>
            <button onClick={() => controller.toggle()}>
                {state.selectedOption?.label ?? "Select…"}
            </button>
            {state.open ? (
                <ul>
                    {state.filteredGroups.flatMap((group) =>
                        group.options.map((option) => (
                            <li key={String(option.value)}>
                                <button onClick={() => controller.commitOption(option)}>
                                    {option.label}
                                </button>
                            </li>
                        )),
                    )}
                </ul>
            ) : null}
        </div>
    );
}
```

  </TabItem>
  <TabItem label="Vanilla / Web Components">

```ts
import { SingleSelectBoxController } from "@select-box/core";

const controller = new SingleSelectBoxController({ options: fruits });
controller.subscribe(() => render(controller.getState()));
render(controller.getState());

function render(state) {
    // Build DOM imperatively, or rebuild your shadow tree, or hand to
    // whatever rendering layer you prefer — the snapshot is plain data.
}
```

  </TabItem>
</Tabs>

## Owning the value

Pass `defaultValue` and the box keeps its own selection. Pass `value` instead and
the box becomes controlled: it shows what you say it holds, and a pick you do not
answer through `onChange` is reverted. That is the shape a form library expects,
and it applies even while the control is `disabled` — the flags refuse the user,
not the page.

```tsx
const [fruit, setFruit] = useState<string | null>("apple");

<SelectBox options={fruits} value={fruit} onChange={setFruit} />;
```

Every wrapper offers the same thing under its own door: a `value` prop in React
and Vue, a `value` property on the two custom elements, and `box.setValue()` on
the jQuery instance.

## Which one

Start ready. The styled component also hands you `root` and `controller`, so
most escape hatches do not cost you the whole tier — see the
[playground](../../examples/playground/) for what the props already reach.
