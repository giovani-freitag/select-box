after this page is the same component whichever one you picked.

## Add the stylesheet

One stylesheet covers all five wrappers, because they render the same markup.
Import it once, anywhere:

```js
import "@select-box/styles/select-box.css";
```

Colors default to CSS system colors, so it follows the reader's light/dark
preference untouched. Retheme it with the `--sb-*` tokens or your own rules —
see [Styling](../styling/).

## Your first select

Drop a snippet into your app. You get grouped options, substring search and
full keyboard navigation, with no further wiring.

<Tabs syncKey="framework">
  <TabItem label="React">

```tsx
import { SelectBox } from "@select-box/react";
import { useState } from "react";

const fruits = [
    { value: "apple", label: "Apple", group: "Pomes" },
    { value: "pear", label: "Pear", group: "Pomes" },
    { value: "lemon", label: "Lemon" },
];

export function FruitPicker() {
    const [value, setValue] = useState(null);
    return (
        <SelectBox
            options={fruits}
            placeholder="Pick a fruit"
            ungroupedLabel="Citrus"
            onChange={setValue}
        />
    );
}
```

`v-model` is the shortest way in; `:value` with `@change` is the same binding
written out, and is the name the other four wrappers use.

## The options shape

`options` is a flat array. Items that share a `group` key render under one
heading; items without a `group` fall under whatever `ungroupedLabel` you
pass (or stay un-headed when omitted).

```ts
interface SelectOption<TExtra extends object = object> {
    value: string;          // unique identifier — coerced to string on input
    label: string;          // shown in the trigger and the list
    disabled?: boolean;     // skipped by keyboard nav, dimmed in the list
    group?: string;         // bundles options sharing the same key
    // + everything from TExtra rides on the same object
}
```

Need to carry a domain payload (id, slug, icon, metadata)? Layer it on
through the `TExtra` generic — the extra fields ride on the same option
and come back to you intact in `onChange` / `selectedOption`:

```ts
import type { SelectOption } from "@select-box/core";

type Fruit = SelectOption<{ id: number; color: string }>;

const fruits: Fruit[] = [
    { value: "apple", label: "Apple", group: "Pomes", id: 1, color: "red" },
    { value: "pear", label: "Pear", group: "Pomes", id: 2, color: "green" },
];
```

`value` is always a string (numeric input is silently coerced — mirrors
`<option value>` in HTML); identity comparisons (`defaultValue`, the
internal `value → option` index, form serialization) use plain `===`.

## Filtering

The default filter is `SubstringFilterStrategy` — case-insensitive
substring match on `label`. Swap it for bitap fuzzy matching, which tolerates
typos and transposed characters rather than only gaps, by passing the strategy
explicitly:

```ts
import { FuzzyFilterStrategy } from "@select-box/addon-fuzzy";

<SelectBox
    options={fruits}
    filter={new FuzzyFilterStrategy()}
    placeholder="Pick a fruit"
/>;
```

Or implement your own — `OptionFilterStrategy<TExtra>` is a single-method
contract:

```ts
interface OptionFilterStrategy<TExtra extends object = object> {
    filter(
        options: ReadonlyArray<SelectOption<TExtra>>,
        query: string,
    ): ReadonlyArray<SelectOption<TExtra>>;
}
```

The controller calls your `filter()` on every keystroke; if you sort the
result, that order shows up in the popover.
